## Required outcomes

1. **Rounded identity and terminal typography.** Preserve the rounded `Fredoka`/`Nunito` personality that currently looks good for `whoami`. Align the `:3` with “Lyra Phasma” on the same baseline/row at desktop and mobile; inspect the actual markup and fix the layout rather than nudging it with brittle offsets. Render the output of `cat /etc/tagline` in the existing self-hosted `JetBrains Mono` font, including the value itself; keep normal body copy in its intended rounded font.

2. **WhiskerFrame animation.** Clicking the mascot must select a valid randomized starting animation frame/state, not reset/jitter back to frame zero. Inspect the real SVG/sprite/state implementation and preserve idle, hover, click, and keyboard behavior. Make randomness bounded and testable; repeated clicks must remain smooth and not leak timers/listeners.

3. **Global click feedback and cursor.** Make the existing native cat-ear/paw cursor more visible and noticeably larger using the current assets or appropriately optimized variants; keep a native CSS cursor, visible hotspot/outline, fallbacks, text-input I-beam, and touch/reduced-motion support. Increase the size/readability of click-reaction text. Add a lightweight delegated click-feedback effect throughout the site so every normal click gets a brief, legible, on-brand response, without blocking links/forms/buttons, text selection, keyboard use, or page navigation. Prevent native drag-and-drop of text/images without disabling normal text selection and copy. Keep images/SVGs non-selectable and non-draggable; never set `user-select: none` on `body` or general text containers.

4. **WhiskerFrame click-powered boss fight.** After 10 mascot clicks, unlock a progressive, speed-based boss fight: track click cadence/bursts with decay so sustained fast clicking increases power, then move WhiskerFrame toward the center, intensify themed page shake, shift the palette progressively pinker with restrained warm-orange accents, and reveal two growing terminal panels on the left/right that type staged fictional command output (install Git/Python, clone demo repositories, then mock `nmap`/Wireshark activity). Finish at a clear maximum-power state with a satisfying visual payoff and an understandable reset/replay path. This is a purely fictional, client-side animation: **never execute displayed commands, install packages, access the filesystem, spawn processes, scan networks, launch Wireshark, or make network requests.** Use synthetic terminal output and non-routable documentation/example targets only as text. Keep controls usable, prevent layout/scroll breakage, support keyboard activation and Escape/reset, cap timers/effects, avoid rapid flashing, honor `prefers-reduced-motion`, and provide a reduced-intensity/stop path. The ordinary site must remain usable before, during, and after the easter egg.

5. **Hero sparkle regression.** Fix `<span class="hero-sparkle-star star-bl">01</span>` (or its current equivalent) being stranded at the far-left edge. Make the hero's sparkle container the intentional positioning context, keep decorative elements within the hero composition, and verify z-index, clipping, and responsive positions at 360px and 1280px. Decorative stars must not intercept pointer events or become noisy to assistive technology.

6. **FOSS banner color.** The background behind “REBEL against corporate greed. REVEL in Free and Open Source Software!” must no longer be indigo/blurple. Compare at least two theme-compatible alternatives (for example deep plum/near-black or a considered pink-led sticker treatment), render screenshots, and choose the best-looking accessible option. Maintain the pastel-on-dark visual language and verify all foreground/background pairings with the existing contrast checker. Do not casually rewrite the entire global token palette.

7. **Public contact address.** Update the site's public contact address in `content/site.yaml` to `lyraphasma@gmail.com` (explicitly supplied by the site owner for this change). Preserve the existing obfuscation/privacy behavior and ensure contact CTAs, mailto links, and generated pages consistently use the configured value; do not copy the address into unrelated metadata or logs.

8. **Repeatable Lighthouse feedback loop.** Add a discoverable, repeatable project command (for example `just lighthouse`) and any small script/config it needs to build/freeze and serve the local static site, run Lighthouse, and save readable HTML plus machine-readable JSON reports under a documented `reports/lighthouse/` path. Include **Performance and SEO** at minimum; include Accessibility and Best Practices where supported. Audit mobile and desktop for the homepage and key routes. The agent must run the audit before/after website-affecting changes, read the findings, fix the highest-impact genuine issues, rerun, and repeat until target thresholds are met or a concrete environment/product blocker is documented. Aim for Performance and SEO scores of at least 90, ideally 95+, without score gaming; preserve the existing <300 KB initial-load and LCP <2.5s design budgets. Add a concise summary of final scores and top findings to durable project state/handoff.

9. **SEO and AI-readable site files.** Audit the actual served/frozen HTML (not only templates) for accurate unique titles/descriptions, canonical URLs, Open Graph/Twitter metadata and real image paths, semantic headings/landmarks, crawlable links, alt text, robots directives, sitemap correctness, and appropriate structured data only where supported by real facts. Fix broken/stale metadata references. Create root-published `/llms.txt` and `/llms-full.txt` from public, currently published pages and keep them synchronized with the actual site routes and content. Follow the current proposal at https://llmstxt.org/ for `llms.txt` (Markdown overview, short summary, curated canonical links); treat `llms-full.txt` as the explicitly requested extended companion convention, **not** as a required part of the core proposal. Do not include private, hidden, draft, or secret content. Add tests that confirm both files are present and accurate in the frozen output. Keep `robots.txt` and `sitemap.xml` valid. Follow Google's established guidance at https://developers.google.com/search/docs/fundamentals/seo-starter-guide and https://developers.google.com/search/docs/fundamentals/get-started; neither `llms.txt` nor SEO changes guarantee indexing or rankings.
